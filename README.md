# Website Authoring Rules

This site is generated by `build_pages.py`.
Run this after content edits:

```bash
py build_pages.py
```

## Structure

- Root listing pages are generated: `index.html`, `films.html`, `exhibitions.html`, `about.html`, `bio.html`, `cv.html`, `press.html`.
- Project pages are generated from folders inside:
  - `works/`
  - `exhibitions/`
- About-related source files are in `about/`:
  - `about/bio.txt`
  - `about/cvintro.txt`
  - `about/cv.txt`
  - `about/press.txt`
  - `about/Paul-Fritz-portfolio.pdf`

## Folder/File Naming Rules (for project media)

These rules apply to image filenames and project folder names (caption parsing in `caption.py`):

- `-` means a space.
- `--` means a literal hyphen.
- `~` becomes double en-space (`&ensp;&ensp;`).
- `NN-` at the start is an ordering prefix (for sorting) and is stripped in captions.

Examples:

- `01-Paul-Fritz,-Title.jpg` -> caption text without `01-`.
- `site--specific` -> `site-specific`.

## Project Text Files

Inside each project folder (`works/<project>/` or `exhibitions/<project>/`):

- `project.txt`: intro text block before media.
- `NN-project.txt` (for example `01-project.txt`): inserts text near media with the same number.
- `credits.txt`: rendered at the end under `CREDITS:`.
- `video.txt`: Vimeo entries.

### `video.txt` format

One video per line:

```txt
https://vimeo.com/123456789
https://vimeo.com/123456789 | Caption text
https://vimeo.com/123456789 | 02-Caption text | 4:3
```

Rules:

- Blank lines and lines starting with `#` are ignored.
- Optional `NN-` in caption controls placement among numbered media.

## TXT Authoring Rules (all txt content sources)

Applies to txt-driven content (`home.txt`, `project.txt`, `NN-project.txt`, `credits.txt`, `about/bio.txt`, `about/cv.txt`, and `about/press.txt` labels):

- Blank line = new paragraph.
- Lines starting with `#` = comments (not rendered).
- Use explicit inline tags:
  - Italic: `<em>text</em>`
  - Bold: `<strong>text</strong>`
  - Underline: `<u>text</u>`
  - Link: `<a href="URL-or-path">Label</a>`
  - Strikethrough `<s>...</s>`
- Links from txt are rendered with:
  - `target="_blank"`
  - `rel="noopener noreferrer"`
  so they open in a new tab/window.
- `_text_` is treated as literal text (no italic conversion).
- Unknown HTML is escaped by default; only supported inline tags above are preserved.
- In `about/press.txt`, labels use the same formatting tags; link tags inside labels are escaped (each press row is already an outer link from the URL column).

Exceptions:

- Image/figure captions generated from filenames still follow the filename convention parser in `caption.py`.
- `video.txt` captions also follow the same filename-style caption conventions (for example `-` for spaces, `_text_` for italics).

## Press Source Format

`about/press.txt` uses one item per line:

```txt
Display label | https://example.com/article
```

Rules:

- Blank lines and lines starting with `#` are ignored.
- Left side (label) supports the same inline tags from TXT Authoring Rules.
- `press.html` is generated from this file.

## CV-Specific Rules (`about/cv.txt`)

`cv.txt` uses a dedicated renderer on top of the shared txt rules:

- Optional intro file: `about/cvintro.txt`
  - Rendered before the CV list.
  - Uses normal txt rules (same behavior as bio/home text), not category-aware CV parsing.

- Category line: `<cat>Section Title</cat>`
  - Renders as a bold section heading.
- Legacy category line: `<strong>Section Title</strong>`
  - Also treated as a category heading.
- Any other non-empty line becomes a bullet point.
- Entry convention for bullet lines:
  - `DATE TITLE / DETAILS`
  - Auto-italic title formatting is applied only under these categories:
    - `<cat>Films</cat>`
    - `<cat>Selected Group Exhibitions</cat>`
    - `<cat>Selected Personal Exhibitions</cat>`
  - In those categories, output becomes: `DATE` + en-space + italic `TITLE`, then plain ` / DETAILS`.
  - In all other categories, output becomes: `DATE` + en-space + plain `TITLE`, then plain ` / DETAILS`.
  - The slash and everything after it are not italic.

Example:

```txt
<cat>Selected Group Exhibitions</cat>
2026 Another Puppet Show / curated by Antoine Champenois / Pantin (FR)
2025 Spindream / Art Geneva / Geneve (CH)
```

## Recommended Workflow

1. Edit txt/image/video source files.
2. Run `py build_pages.py`.
3. Optionally run tests:

```bash
py -m unittest -v
```
